## 점수

- 색·종류: 동일 표준 ID 각 3점. 기타 제외.
- 장소: 동일 또는 급식실↔급식실 앞이면 2점. 교실·계단·화장실·정수기·신발장은 세부 위치도 같아야 함. 기타·모름 제외.
- 날짜: 차이 3일 이내 2점.
- 특징: 공백·문장부호로 나눈 두 글자 이상 공통 단어가 있으면 2점. 형태소·동의어 분석 없음.
- 동점: 날짜 차이가 작은 순, ID 순. 0점·동일 유형·반환 완료 제외.
- 최대 12점은 규칙의 합이며 일치 확률이 아님.
- 실제 학교 시설을 확인한 목록은 아니며 장소 확인 후 보완 필요.

## 데이터와 권한

브라우저에는 공개용 publishable key만 포함한다. 서비스 권한 키는 Supabase Edge Function 환경 변수에서만 사용한다. 테이블은 RLS 활성화 및 anon/authenticated 직접 접근 차단. 공개 조회·등록은 입력을 검증하는 Edge API를 통해 제공한다.

브라우저에 256비트 관리 토큰을 생성·보관하고 서버에는 SHA-256 해시만 저장한다. API는 토큰·해시를 응답에 포함하지 않는다. 반환 완료는 해당 게시글의 토큰 해시가 일치할 때만 허용한다. 학교 구성원 인증이나 실명 인증은 아니다.

다른 기기·브라우저로 관리 권한이 이전되지 않으며 브라우저 데이터 삭제 시 복구할 수 없다. 입력 내용은 공개되므로 이름·연락처 입력을 피하도록 화면에서 안내한다.

최신 200건을 조회·추천한다. 브라우저별 시간당 20건의 기본 등록 제한이 있지만 토큰 재생성·동시 요청을 막는 강한 남용 방지는 아니다. 대규모 운영 전 로그인·CAPTCHA·원자적 속도 제한이 필요하다.

서버 소스는 server/index.ts, 스키마 기록은 server/schema.sql. Edge 배포 시 categories.js를 같은 경로에 포함한다. 서버 폴더는 Vercel 정적 배포에서 제외한다. sample-data.js는 과거 임시 검사 자료이며 실제 화면에서 로드하지 않고 배포에서도 제외한다.

Supabase 보안 검사에 오류·경고는 없고 RLS Enabled No Policy 정보 항목 1건이 있다. 클라이언트 직접 접근을 막고 서버만 접근하는 설계이므로 공개 허용 정책을 만들지 않았다. 설명: https://supabase.com/docs/guides/database/database-linter?lint=0008_rls_enabled_no_policy

## 검증

상위 폴더에서 node tmp/verify-db.cjs로 실제 DB와 로컬 화면을 검사한다. TEST_URL을 배포 주소로 설정하면 배포본을 검사한다. 테스트가 생성한 임시 글은 실행 후 tmp/db-test-ids.json의 해당 ID만 정리한다.

- tmp/verification-db.json: 로컬 실제 DB 검사.
- tmp/deployment-db-verification.json: 배포본 전체 검사.
- tmp/verify-matching-core.cjs: 점수 경계값·동점·제외 조건 검사.
- 저장·재조회·추천·반환, 타 작성자 변경 거부, 직접 DB 접근 거부, 서버 입력 검증, 통신 실패 안내, 390px·320px 화면 확인.
- 10/26 검증용 글은 정리 완료. 실제 모바일 기기 검사는 아님.
